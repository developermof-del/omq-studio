# عُمق | موقع الاستوديو ودليل الهوية

واجهة عربية من اليمين إلى اليسار تعرض الأعمال الفنية والقطع المطبوعة ثلاثية الأبعاد، وتجمع الأصول المعتمدة لهوية عُمق. الموقع ثابت: تُنشر محتويات **`site/`** مباشرةً، دون خادم أو حزم Node أو قاعدة بيانات. يقدّم GitHub Pages الموقع، وتبقى عمليات الشراء والدفع في متجرك الفعلي على سلة.

## ماذا يوجد في الموقع؟

| الوجهة | الملف أو الإعداد |
| --- | --- |
| مدخل الاستوديو وتصفّح الأعمال | [site/index.html](site/index.html) |
| المعرض وتفاصيل كل قطعة | [site/collection.html](site/collection.html) |
| دليل اللون والخط والشعار وحركته وتنزيل الملفات | [site/brand.html](site/brand.html) |
| معاينة الحساب والمحتوى لكل منصة | [site/platforms.html](site/platforms.html) |
| التنزيل الكامل لحزمتَي الهوية والتواصل | [site/download.html](site/download.html) — يصل الزائر إليها من مكتبة التنزيلات |
| ربط القطع بصفحات منتجات سلة | [site/assets/site-config.js](site/assets/site-config.js) |
| إعداد النشر عند تحديث الفرع الرئيسي | [.github/workflows/pages.yml](.github/workflows/pages.yml) |

الصور الظاهرة نماذج توضيحية لهوية الاستوديو. قبل تفعيل الشراء استبدل صور الدراسات بصور منتجاتك، وراجع أسماءها وخاماتها وأبعادها ووصفها في الموقع وفي المتجر.

## معاينة على الماك قبل النشر

فكّ الضغط عن **الحزمة كاملةً**. افتح Terminal داخل المجلد الذي يحتوي هذا الملف ونفّذ، إن كان Python 3 متاحًا:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory site
```

افتح [المعاينة المحلية](http://127.0.0.1:8000/). لإيقافها اضغط `Ctrl+C`. استخدم الخادم المحلي عند اختبار التنزيلات؛ فتح ملفات HTML عبر `file://` لا يمثّل سلوك GitHub Pages. لا تفتح ملفات الأجزاء الثنائية فرادى: زر التنزيل يجمع الحزمة ويتحقق من سلامتها.

## نشر الموقع من GitHub Desktop

1. أنشئ في حسابك على GitHub **مستودعًا جديدًا وفارغًا** باسم تختاره، مثل `omq-studio`. في GitHub Free اختر **Public**. لا تضف README من شاشة إنشاء المستودع؛ هذه الحزمة تحتوي واحدًا.
2. في GitHub Desktop اختر **File → Clone Repository** وحدد المستودع الجديد. افتح مجلده في Finder. انسخ **محتويات مجلد المشروع** المفكوك إلى جذر المستودع، بحيث ترى `site` و`scripts` و`README.md` و`.github` في المستوى نفسه. على الماك اضغط **⌘ ⇧ .** لإظهار الملفات المخفية والتأكد من نسخ `.github/workflows/pages.yml`. لا تنسخ أي مجلد باسم `.git`؛ احتفظ بمجلد Git الذي أنشأه Desktop.
3. في GitHub Desktop تأكد أن الفرع اسمه **main**؛ إن كان اسمه مختلفًا غيّره إلى main قبل الدفع الأول. اكتب وصفًا للتغيير، ثم اختر **Commit to main** و**Push origin** أو **Publish branch**.
4. افتح على GitHub **Settings → Pages → Build and deployment → Source** واختر **GitHub Actions**. يرفع الملف المرفق مجلد `site/` فقط. لا تختر النشر من جذر الفرع، ولا تنشئ سير عمل ثانيًا من القوالب المقترحة.
5. من **Actions → Publish OMQ to GitHub Pages → Run workflow** اختر **main**. بعد نجاح مهمة **deploy** افتح الرابط الذي تعرضه المهمة أو زر **Visit site** في إعدادات Pages. لمستودع مشروع اعتيادي يكون شكل العنوان `https://ACCOUNT.github.io/REPOSITORY/`، والرابط الذي تعرضه GitHub هو المرجع النهائي.
6. مستقبلًا، بعد تعديل ملفات `site/` نفّذ **Commit + Push** إلى `main`. سيُعاد النشر تلقائيًا، ولا تحتاج إلى إعادة الإعداد. إذا لم تظهر مهمة النشر، تحقّق أن GitHub Actions مسموح به للمستودع وأن ملف سير العمل موجود في مكانه على `main`.

## نشر سريع عبر Terminal (بديل)

مناسب عند استخدام Git و[GitHub CLI](https://cli.github.com/) على الماك. شغّل الأمر **من نسخة مفكوكة حديثًا خارج مستودع Git آخر**. يجب أن يكون اسم وإيميل مؤلف الالتزام مضبوطين محليًا في Git. الأمر ينشئ مستودعًا **عامًا جديدًا** تحت حسابك المسجّل، ويحفظ رابط `origin` للمجلد، ويدفع الملفات، ثم يفعّل Pages ويطلب أول نشر.

```sh
gh auth login --hostname github.com
bash scripts/publish-github.sh --public omq-studio
```

استبدل `omq-studio` باسم جديد متاح. تتوقف الأداة عند وجود المستودع ولا تستبدله. لا يحتاج الموقع إلى إضافة **Secrets**. تستعمل الأداة تسجيل دخول `gh` المحلي؛ **لا تضع كلمة مرور أو رمز وصول في ملفات المشروع**. إذا رفض حسابك إعداد Pages، اتبع الخطوتين ٤ و٥ في القسم السابق. إذا رُفض دفع ملف سير العمل لحساب يستخدم OAuth أو PAT كلاسيكيًا، راجع إذن تحديث workflows في جلسة GitHub CLI أو ادفع من GitHub Desktop.

## ربط منتجات سلة الحقيقية

افتح [site/assets/site-config.js](site/assets/site-config.js). استبدل القيمة الفارغة لكل قطعة **برابط HTTPS الحقيقي لصفحة تلك القطعة** في سلة. المفاتيح الحالية `fold` و`arch` و`arcade` هي معرّفات دراسات العرض، ويجب ربط كل واحد بالمنتج الصحيح بعد تحديث المحتوى. يُترك الحقل فارغًا لأي عمل لم يُطرح للبيع؛ عندها لا يعرض الموقع زر شراء له. عند نجاح الدفع في سلة تبقى الفاتورة والطلب والتتبّع ضمن سلة، ولا يجمع الموقع بيانات دفع.

لإبقاء Pages معرضًا ودليلًا للهوية، اجعل البيع الفعلي على سلة. إذا أصبح الغرض الأساسي للموقع عرض بضائع لإتمام معاملات تجارية، استخدم استضافة تجارية لواجهة المتجر مع إبقاء المصدر على GitHub؛ توضح [حدود GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) هذا الفرق.

## صيانة الأصول

- احتفظ بمسارات الصور والخطوط وملفات SVG **نسبية** حتى يعمل الموقع داخل المسار الفرعي للمستودع بلا إعداد إضافي.
- تعديل [site/brand.html](site/brand.html) يحدّث النص أو أزرار الأصول في دليل الهوية. لا تمدّد الشعار؛ استبدل صور الأعمال فقط عند تحديث المعرض.
- حزم الهوية والتواصل منشورة على شكل أجزاء في `site/assets/downloads/` مع وصفها في `site/assets/kit-index.js`. عند تعديل حزمة يجب إعادة بناء الأجزاء وقائمة أسمائها وأحجامها وبصمة SHA-256 لتطابق الأرشيف الجديد؛ نقل ملف منفرد أو تغيير اسمه لا يحدّث الروابط الأخرى. الحزمتان المرفقتان جاهزتان كما هما.
- لمراجعة ملفات GitHub بعد النشر: يدخل الزائر إلى رابط Pages، أما تعديل الملفات فيتم من المستودع أو من نسخة Desktop المتصلة.
